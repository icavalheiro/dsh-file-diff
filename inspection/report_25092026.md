# dsh-file-diff — Security & Claims Audit Report

**Date:** 2026-09-25
**Scope:** Full source review of the `dsh-file-diff` package (`README.md`, `package.json`, `lib/`, `scripts/`) to verify (1) whether the plugin is safe and (2) whether it actually does what the README claims.

---

## 1. Is the plugin safe? ✅ Yes

**Attack surface is effectively nil:**

- **No network access**: no `fetch`, `XMLHttpRequest`, `WebSocket`, `http(s)` clients, `sendBeacon`, or any external communication in any file.
- **No dangerous dynamic execution**: no `eval`, `new Function`, `child_process`, `execSync`, or spawn. The only "dynamic code" is the tokenizer's `RegExp`, built from fixed literal strings (not user data).
- **No sensitive storage access**: no `localStorage`, cookies, `crypto`, etc.
- **Single runtime dependency**: `require('react')` — the platform's own seed, as declared in the README and confirmed in code.
- **Node half (`lib/index.js`) is a no-op** — it touches nothing on the host.
- **Bundle integrity verified**: the build was reproduced in memory (`styles.css` + `client.template.js` → `client.js`) and the result matches the on-disk `lib/client.js` exactly (the only difference was CRLF vs LF line endings). There is no hidden code in the generated file beyond what is in the template.
- **Limited DOM scope**: injects its own `<style>` tag (removed on cleanup) and registers components into specific UI slots. No global manipulation.

## 2. Does it do what the README says? ✅ Yes, accurately

| README claim | Verified in code |
|---|---|
| "N modified files" row at the end of each turn | `FileDiffRow` registered on `conversation.chat.turnTail` with `select: selectFileDiffs` ✔ |
| "Change history" button in the session header | `SessionChangesButton` on `conversation.session.header.utilities` ✔ |
| Right-sidebar tab (kind `filediff`) | `sidebarRightTabs.register({ id: 'dsh-file-diff', kind: 'filediff' })` + bodies on `sidebar.right.pane.tab(.title)` ✔ |
| Compact LCS diff engine | `diffRows()` implements the classic LCS DP correctly ✔ |
| Two data sources (turn node data + Trajectory ledger) | `selectFileDiffs` reads `turn.data.get('filediff')`; `collectSessionChanges` rebuilds from `eventNodes`/`eventLocations` — tab body is stateless, as described ✔ |
| Built-in tokenizer for `.gd`/`.gdshader`/`.gdresource` (+ ~25 other languages) | `LANG_BY_EXT`, `KEYWORDS`, `makeGrammar`/`makeLineHighlighter` with multi-line block-comment state ✔ |
| Plugin-owned Godot file preview in the sidebar | `documentPreviews.register({ id: 'dsh-file-diff/gd-preview', extensions: [...], priority: 'extension' })` + body on `sidebar.right.tab.document` ✔ |
| Only `require('react')`, no external dependencies | Confirmed — the bundle performs only that require ✔ |
| Safe degradation when `ctx.get(...)` is unavailable | All `ctx.get` calls are guarded with `!== undefined`, and `openSidebar` has a double try/catch, as documented ✔ |

### Minor observations (do not affect safety or claims)

1. **Performance**: the LCS diff is O(n·m) per hunk, and `countDiffLines` recomputes the full diff just to count lines — this can be heavy in the browser for large files, but it is a simplicity trade-off, not a bug.
2. **Simplified tokenizer**: compact regex grammar, so highlighting may be imperfect on edge cases (e.g., strings with exotic escapes) — expected and declared as a limitation of the "pure plugin approach".
3. The `edit` tool only counts when `old_string !== new_string` — sensible behavior.

## Verdict

Clean code, honest README, no telemetry, no network, no execution of unauditable code. Safe to install following the package's own README instructions (link/junction in `profiles/web/node_modules` + composition line in `cordis.patch.yml`).
